feat: UI Guided Flow

improved the Government Health Schemes Discovery Engine flow. The changes focused on upgrading the architectural foundation of the API layer and revamping the user interface to be more scalable, intuitive, and visually organized.

summary of all the key accomplishments:

 1. Centralized API Service Layer & Environment Configuration
- Environment Variables: We introduced an `.env` configuration file to store `EXPO_PUBLIC_API_URL`. This allows the Expo frontend to point to the backend (e.g., port `8080` or `8000`) dynamically without hardcoding URLs deep within the codebase.
- Service Abstraction: We removed large blocks of inline `fetch()` logic from `ChatScreen.js`. Instead, we created a robust `apiClient.js` that automatically intercepts requests to inject essential headers like `X-Device-ID`.
- Modular Endpoints: We created `apiService.js`, mapping dedicated JavaScript functions to your FastAPI backend endpoints (e.g., `searchSchemesRAG`, `getHealthcareSchemes`, `getNearbyFacilities`, and `getStates`).

 2. Dynamic State Selection Integration
- Removed Hardcoding: Rather than manually hardcoding the list of Indian States inside `ChatScreen.js`, the app now invokes the backend `/api/v1/schemes/healthcare-schemes/meta/states` endpoint.
- On-Mount Fetching: When the chat screen loads, it populates the `availableStates` state variable dynamically, keeping the frontend seamlessly synchronized with any updates to regions in the backend database.
- Enforced UI Prompts: We corrected a bug in the chat bot's logic where clicking the "Know Govt Schemes" button would silently skip the state-selection process if a state was previously cached in `AsyncStorage`. The button now *always* triggers the state-selection modal, giving the user explicit control over their search criteria.

 3. Complete Revamp of Scheme Detailed Views
- Compact Scheme Cards: The original `SchemeCard.js` design suffered from vertical bloat due to an infinite-scrolling "Read More..." accordion that attempted to display all eligibility and benefit text inline. We stripped this back to a compact, uniform card displaying only the title, department, level badge, and a 3-line brief description.
- New "View Details" Flow: The accordion was replaced with a prominent "View Details" action button, transitioning the user from the high-level chat context to a focused deep dive.
- Tabbed Modal Interface (`SchemeDetailsModal.js`): We engineered a brand-new, polished bottom-sheet modal to display comprehensive scheme data. 
  - On-Demand Fetching: Upon opening, the modal uses the new `getSchemeDetails` API wrapper to query the backend's `/{id_or_slug}` endpoint, fetching the precise relational SQL records for that scheme.
  - Horizontal Navigation: The data is elegantly divided into scrollable, horizontal pill-tabs: `Overview`, `Benefits`, `Eligibility`, `Documents`, `Process`, `FAQs`, and `References`.
  - Clean Presentation: Users can navigate massive amounts of information quickly and cleanly, viewing required documents as bulleted lists, FAQs in structured Q&A cards, and external references as clickable links.

 4. Stability & Polish
- Global Logger: Updated the application's global logger to respect the `.env` URL, ensuring client-side crashes and interactions are correctly logged to the actively running backend port.
- Chat History Restoration: Fixed earlier persona logic issues to ensure that default chats (Meta AI, Aarogya Mitra) persist and initialize correctly without overriding user configurations.

These updates have transformed the "Know Govt Schemes" feature from a simple text-based interaction into a production-ready, highly interactive guided discovery engine.
